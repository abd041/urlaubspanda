Offer Detail Page – Additional Requirements Desktop Version The right-hand booking / price column must be sticky . When the user scrolls down the offer page, the price card including the CTA button should remain visible on the right side of the screen. The sticky element should contain the main booking information, especially: Old price Current price Saving / discount Main CTA button : „Termine &amp; Preise anzeigen“ The sticky behaviour should stop naturally before the footer or other page elements so it never overlaps content. Mobile Version On mobile, the normal CTA button should first appear inside the page content in the price section. Once the user scrolls far enough that this original button is no longer visible, a sticky CTA bar/button should appear at the top of the screen . The sticky version should remain visible while the user continues scrolling. Important : Do not show both buttons at the same time. The sticky CTA should only appear once the original CTA has left the viewport. When the user scrolls back up and the original button becomes visible again, the sticky version should disappear. The CTA should be visually prominent and slightly thicker/taller than in the current example. Button text : „Termine &amp; Preise anzeigen“ Urlaubspanda blue background White bold text Large tap area Rounded corners A button height of approximately 60–64 px on mobile would work well. „Mehr Infos zum Angebot ansehen“ Directly below the normal CTA button on mobile, display the text link: „Mehr Infos zum Angebot ansehen“ Optionally include a small downward chevron. When clicked, the page should smooth-scroll directly to the written offer description further down the page. For example : Mehr Infos zum Angebot ansehen ↓ This is not a second primary CTA and should therefore visually remain a simple text link. Share Button There should be a share button next to the hotel name / hotel heading area . On mobile, it should be easy to reach and clearly visible near the top of the offer page. When the user clicks the share icon, open a small modal, bottom sheet or native share dialog with the following options: Link kopieren WhatsApp SMS Messenger E-Mail Where supported, the browser's native Web Share API can be used on mobile. If native sharing is not supported, use our own share modal as fallback. The shared URL must always point directly to the current offer. CTA Destination Behaviour The CTA „Termine &amp; Preise anzeigen “ needs to support two possible behaviours on a per-offer basis. This should ideally be configurable in the backend. Option A – Direct Redirect For offers that use only one destination link: User clicks : „Termine &amp; Preise anzeigen“ → User is immediately redirected to the configured booking / affiliate link. No additional popup is shown. Option B – Country Selection Before Redirect For some offers, different booking links may exist depending on the customer's country of residence. When the user clicks: „Termine &amp; Preise anzeigen “ open a clean modal or bottom sheet asking: „Wo wohnst du?“ Subtitle : „Wähle dein Land, damit wir dir das passende Angebot zeigen können.“ Then display three large selectable options: 🇦🇹 Österreich 🇩🇪 Deutschland 🇨🇭 Schweiz After selecting a country, immediately redirect the customer to the corresponding configured booking link. For example: Austria → affiliate_url_at Germany → affiliate_url_de Switzerland → affiliate_url_ch The country selection should not be hardcoded into the frontend . Each offer should be able to have its own destination URLs. If an offer only has one booking URL, the modal should not appear at all. Backend Logic Each offer should ideally support something like: cta_mode : - direct - country_selection For a direct offer: cta_mode : direct booking_url : ... For country-specific offers: cta_mode : country_selection booking_urls : AT: ... DE: ... CH: ... This will allow us to decide separately for every deal whether the visitor should be redirected immediately or first select their country.
